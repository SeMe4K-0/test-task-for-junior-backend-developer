# Task Service

Сервис для управления задачами с HTTP API на Go.

## Требования

- Go `1.23+`
- Docker и Docker Compose

## Быстрый запуск через Docker Compose

```bash
docker compose up --build
```

После запуска сервис будет доступен по адресу `http://localhost:8080`.

Если `postgres` уже запускался ранее со старой схемой, пересоздай volume:

```bash
docker compose down -v
docker compose up --build
```

Причина в том, что SQL-файл из `migrations/0001_create_tasks.up.sql` монтируется в `docker-entrypoint-initdb.d` и применяется только при инициализации пустого data volume.

Базовый префикс API:

```text
/api/v1
```

Основные маршруты:

- `POST /api/v1/tasks`
- `GET /api/v1/tasks`
- `GET /api/v1/tasks/{id}`
- `PUT /api/v1/tasks/{id}`
- `DELETE /api/v1/tasks/{id}`
- `POST /api/v1/tasks/materialize`
- `GET /api/v1/tasks/rules`
- `DELETE /api/v1/tasks/rules/{id}`

## Реализация периодичности

### Подход

Периодические задачи хранятся как правила (`task_rules`), а не как набор конкретных записей в БД. При запросе `GET /tasks` виртуальные задачи генерируются из правил и становятся реальными.

Это позволяет:
- не хранить тысячи записей для долгосрочных правил
- легко менять правило без пересоздания всех задач

### Виртуальные и реальные задачи

Виртуальная задача — это задача, сгенерированная из правила, но ещё не сохранённая в БД. Она отличается полем `is_virtual: true` и `id: null`.

Чтобы зафиксировать виртуальную задачу (например, изменить статус или добавить комментарий) — её нужно материализовать через `POST /api/v1/tasks/materialize`. После этого она становится обычной задачей с реальным ID.

### 
**Получение задач** возвращает реальные задачи из бд и виртуальные задачи, сгенерированные по правилам
**Материализация** создаёт реальные задачи на основе task_rule
**Удаление правила**:
- правило удаляется
- существующие задачи сохраняются
- rule_id становится null

### Типы периодичности

| Тип              | Параметры                          | Пример                      |
|------------------|------------------------------------|-----------------------------|
| `daily`          | `interval` — каждые N дней         | `{"interval": 2}`           |
| `monthly`        | `days` — список дней месяца (1–30) | `{"days": [1, 15]}`         |
| `specific_dates` | `dates` — конкретные даты          | `{"dates": ["2026-04-15"]}` |
| `even_days`      | нет                                | `{}`                        |
| `odd_days`       | нет                                | `{}`                        |

## Примечания

**Monthly**: допустимые дни от 1 до 30 согласно тз
- **Управление правилами**: 
- правило периодичности задаётся только при создании задачи и в дальнейшем не меняется — если расписание нужно изменить, создаётся новое правило.
- при удалении правила виртуальные задачи исчезают, материализованные — сохраняются со статусом и историей.
**Обновление периодичности**: `PUT /tasks/{id}` не поддерживает изменение правила. Если передать поле `recurrence` — вернётся ошибка `400`.
**Создание периодической задачи**: `POST /tasks` с полем `recurrence` создаёт правило и возвращает виртуальный таск с первой датой по расписанию (`id: null`, `is_virtual: true`).
**Дедупликация**: если на дату уже существует материализованная задача, товиртуальная задача НЕ будет сгенерирована
