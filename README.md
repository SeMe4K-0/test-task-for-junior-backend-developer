# Task Service

Сервис для управления задачами с HTTP API на Go.

## Требования

- Go `1.23+`
- Docker и Docker Compose

## Быстрый запуск через Docker Compose

```bash
docker compose up --build
```

После запуска сервис будет доступен по адресу `http://localhost:8080`.

Если `postgres` уже запускался ранее со старой схемой, пересоздай volume:

```bash
docker compose down -v
docker compose up --build
```

Причина в том, что SQL-файлы из `migrations/` монтируются в `docker-entrypoint-initdb.d`
и применяются только при инициализации пустого data volume.

## API

Базовый префикс: `/api/v1`

### Существующие маршруты

| Метод    | Путь                  | Описание                       |
|----------|-----------------------|--------------------------------|
| `POST`   | `/tasks`              | Создать одну задачу            |
| `GET`    | `/tasks`              | Список всех задач              |
| `GET`    | `/tasks/{id}`         | Получить задачу по ID          |
| `PUT`    | `/tasks/{id}`         | Обновить задачу                |
| `DELETE` | `/tasks/{id}`         | Удалить задачу                 |

### Новый маршрут: периодические задачи

| Метод  | Путь               | Описание                                                   |
|--------|--------------------|------------------------------------------------------------|
| `POST` | `/tasks/recurring` | Создать набор задач по расписанию; возвращает массив задач |

## Периодические задачи

### POST /api/v1/tasks/recurring

Принимает описание задачи и правило повторения, создаёт отдельную задачу на каждую
подходящую дату в указанном диапазоне и возвращает список созданных задач.

Каждая задача — самостоятельная единица: её можно редактировать, менять статус и
удалять независимо от остальных. Правило повторения сохраняется на каждой задаче,
чтобы было видно, откуда она появилась.

#### Поля запроса

| Поле         | Тип      | Обязателен | Описание                                                    |
|--------------|----------|------------|-------------------------------------------------------------|
| `title`      | string   | да         | Название задачи                                            |
| `description`| string   | нет        | Описание                                                   |
| `status`     | string   | нет        | `new` / `in_progress` / `done`; по умолчанию `new`         |
| `recurrence` | object   | да         | Правило повторения (см. ниже)                              |
| `start_date` | YYYY-MM-DD | тип†    | Начало диапазона                                           |
| `end_date`   | YYYY-MM-DD | тип†    | Конец диапазона (включительно)                            |

†`start_date` / `end_date` требуются для всех типов, **кроме** `dates`
(там даты передаются внутри `recurrence.dates`).

#### Объект `recurrence`

| Поле         | Тип        | Описание                                                                         |
|--------------|------------|----------------------------------------------------------------------------------|
| `type`       | string     | `daily` / `monthly` / `dates` / `even_odd`                                      |
| `interval`   | int        | **Только `daily`**: повтор каждые N дней (≥ 1)                                 |
| `month_days` | []int      | **Только `monthly`**: числа месяца 1–30; дни, которых нет в месяце, пропускаются |
| `dates`      | []YYYY-MM-DD | **Только `dates`**: конкретные даты                                           |
| `parity`     | string     | **Только `even_odd`**: `"even"` или `"odd"` — чётные / нечётные числа месяца  |

Максимальный диапазон — 365 дней. Максимальное количество дат для типа `dates` — 365.

---

### Примеры запросов

#### Ежедневный обзвон пациентов (каждые 2 дня, апрель)

```json
POST /api/v1/tasks/recurring
{
  "title": "Обзвон пациентов",
  "recurrence": {
    "type": "daily",
    "interval": 2
  },
  "start_date": "2026-04-01",
  "end_date": "2026-04-30"
}
```

#### Инвентаризация по 1-м и 15-м числам месяца

```json
POST /api/v1/tasks/recurring
{
  "title": "Инвентаризация",
  "recurrence": {
    "type": "monthly",
    "month_days": [1, 15]
  },
  "start_date": "2026-04-01",
  "end_date": "2026-06-30"
}
```

#### Формирование отчётности по чётным числам

```json
POST /api/v1/tasks/recurring
{
  "title": "Формирование отчётности",
  "recurrence": {
    "type": "even_odd",
    "parity": "even"
  },
  "start_date": "2026-04-01",
  "end_date": "2026-04-30"
}
```

#### Задачи на конкретные даты

```json
POST /api/v1/tasks/recurring
{
  "title": "Квартальный обход",
  "recurrence": {
    "type": "dates",
    "dates": ["2026-04-15", "2026-07-15", "2026-10-15"]
  }
}
```

## Допущения и проектные решения

1. **Каждый инстанс — независимая задача.** Альтернатива — хранить одну «шаблонную»
   задачу и генерировать инстансы на лету при запросе расписания. Я выбрал первый
   подход: это проще для клиента (все существующие CRUD-операции работают без изменений)
   и надёжнее при редактировании отдельных экземпляров.

2. **`month_days` ограничены значениями 1–30**, а не 1–31. День 31 существует только
   в 7 из 12 месяцев, что делает его ненадёжным для регулярного расписания. Дни 29–30
   в феврале молча пропускаются — это нормальное поведение для расписания.

3. **Максимальный диапазон — 365 дней** за один запрос, чтобы предотвратить
   случайное создание тысяч задач.

4. **`scheduled_date` добавлен и к обычному `POST /tasks`** как опциональное поле —
   это позволяет создать единичную задачу с конкретной датой, не используя механизм
   повторения.

5. **Нет группировки инстансов** (recurrence_group_id и т.п.) — операции "отменить
   все задачи по расписанию" нет в текущих требованиях. При необходимости можно
   добавить отдельной миграцией.
