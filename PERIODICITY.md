# Реализация периодических задач
 добавлена возможность задавать настройки периодичности. Это позволяет автоматически создавать дочерние задачи на определённые даты согласно указанному расписанию

## типы периодичности

В поле `period_conf` передаётся объект с обязательным параметром `type`. В зависимости от типа указываются дополнительные параметры.

| Тип (`type`)      | Параметр                | Описание                                                                 |
|-------------------|-------------------------|---------------------------------------------------------------------------|
| `daily`           | `interval_days` (int)   | Каждый n‑й день, начиная с текущей даты. n ≥ 1.                           |
| `monthly`         | `month_day` (int)       | Задача на определённое число месяца (от 1 до 30).                         |
| `specific`        | `specific_dates` ([]string) | Список конкретных дат в формате `YYYY-MM-DD`.                          |
| `even_odd`        | `even_odd_type` (string)| Задачи только на чётные (`"even"`) или только на нечётные (`"odd"`) дни месяца. |

## Модель данных

В таблицу `tasks` добавлены два новых поля:

- `period_conf JSONB` – хранит конфигурацию периодичности. Присутствует только у **задачи-шаблона**.
- `scheduled_date DATE` – дата, на которую запланирована задача. Присутствует только у **сгенерированных дочерних задач**.

Такая модель позволяет хранить шаблоны и их экземпляры в одной таблице, не создавая избыточных связей.

## Принцип работы

### Создание задачи с периодичностью

1. При POST-запросе с заполненным полем `period_conf` создаётся задача-шаблон.
2. Сразу после сохранения шаблона генерируются дочерние задачи на ближайшие **30 дней** (горизонт планирования).
3. Дочерние задачи наследуют `title`, `description` и `status` от шаблона, но имеют `period_conf = null` и заполненное поле `scheduled_date`.
4. Если создаётся задача без `period_conf`, она считается обычной одноразовой задачей.

### Обновление шаблона

- При PUT-запросе к существующему шаблону с изменённым `period_conf` все **будущие незавершённые** дочерние задачи удаляются, и генерируются новые согласно обновлённому расписанию.
- Это гарантирует актуальность запланированных задач и предотвращает дублирование.

### Удаление

- Удаление шаблона (DELETE) **не удаляет** дочерние задачи автоматически. Это осознанное упрощение для MVP. При необходимости можно добавить каскадное удаление через `ON DELETE CASCADE` на уровне БД.

## Примеры запросов

### Ежедневная задача (каждый день)

```json
POST /api/v1/tasks
{
  "title": "Ежедневный обзвон",
  "description": "Обзвон пациентов",
  "status": "new",
  "period_conf": {
    "type": "daily",
    "interval_days": 1
  }
}
